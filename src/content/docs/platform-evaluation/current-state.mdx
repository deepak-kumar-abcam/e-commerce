## How it is built

- **One central Intershop instance, ICM 14.5**, serves four operating companies. This is the current
  major release, so there is no upgrade backlog behind the comparison.
- **Headless.** Intershop hosts no customer-facing pages. **Adobe Experience Manager (AEM)** is the
  front end for every OpCo on the instance — marketing site and product catalog alike — and its components call
  Intershop's REST APIs **directly**, with no API layer in between.
- **ERP integrations live inside the codebase.** Orders reach Microsoft Dynamics 365 (Phenomenex),
  SAP (Leica Microsystems), and Oracle (SCIEX) through Java cartridges in the shared Intershop
  codebase.
- **Product data is mastered upstream.** The ERPs feed **inRiver**, the central PIM, which
  enriches it and feeds Intershop and Coveo. Files travel through the Danaher Life Sciences SFTP
  server and **Boomi**. Commerce consumes product data, and some list prices, rather than owning
  them. See the [product data flow](/flows/product-data/).
- **Customer data arrives the same way.** For Phenomenex, customers, customer-specific prices,
  quotes, and segments come from the ERP and CRM through WebDB, the SFTP server, and Boomi.
- **Shared services.** Auth0 provides central sign-on for every OpCo on the instance, and **Coveo**
  provides search and recommendations. The full set is on the
  [architecture diagrams](/architecture/). Payments run through Stripe
  (Phenomenex, Leica Microsystems) and Cybersource (SCIEX).

## How it is run

There is **one common codebase**. OpCo technical teams make the changes their business needs, but
code management and deployment are owned centrally by the Danaher Life Sciences platform team.
Every change, for every OpCo, ships through the same build and release.

## Why we are looking

What works:

- **B2B capabilities** we depend on are mature and built in.
- **Customization** has been good enough to meet each OpCo's needs on a shared codebase.

What doesn't:

- **Feature velocity.** New capabilities take a long time to reach production.
- **AI enablement.** New AI capabilities arrive slowly — and since we are on the current release,
  that is a limit of the platform, not of our upgrade cadence.

## The wider estate

The central instance is not the only Intershop in Danaher Life Sciences. Three more OpCos run
Intershop on **their own instances**, each with its own code repository and its own team. This
evaluation does not cover them, but they belong in the picture.

- **Beckman Coulter Life Sciences is joining the central Auth0 tenant.** Once live, it will be the

### A question this evaluation does not answer

Four instances of the same platform raise a bigger question: **should they converge** — onto the
central Intershop instance, onto commercetools, or not at all? An instance that needs a major
upgrade anyway, and OpCos already sharing Auth0, make it a live question. It is deliberately out of
scope until we know more about the other three instances: their integrations, customizations, and
B2B usage.
